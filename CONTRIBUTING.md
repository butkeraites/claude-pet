# Contributing to Zeca

Thanks for wanting to make the little parrot better! Issues, ideas, sprites, bug
fixes, and new platforms are all welcome. This project is meant to be playful and
friendly — please keep that spirit in reviews and discussions.

> The project's working language is Portuguese: `PLANO.md` (the roadmap),
> `DECISIONS.md` (every decision and why), and `PROGRESS.md` (one line per task)
> are in Portuguese, and so are code comments, commits, the CLI, and the pet's
> speech bubbles. **English is used for Rust identifiers and skin keys** (`idle`,
> `done_small`, …). PRs and issues in either language are fine.

## Getting set up

You need [Rust](https://rustup.rs) (stable). Then:

```sh
git clone https://github.com/butkeraites/claude-pet
cd claude-pet
bin/pet verificar        # the gate — run this before every commit
```

`bin/pet verificar` runs formatting, Clippy (`-D warnings`), the whole test
suite, cross-compile checks for Windows/macOS, and lints. **A PR must pass it.**
(Install the cross targets once with
`rustup target add x86_64-pc-windows-msvc aarch64-apple-darwin`.)

To run the pet locally on macOS: `scripts/instalar.sh` (builds from source).

## How it's built

- **`crates/pet-core`** — platform-pure. The brain, animator, skin/raster, the
  Motor (all pet logic), and the platform *traits*. No OS or windowing
  dependencies, on any target; everything is tested against a fake clock and a
  fake window. **New pet behavior goes here**, not in a platform crate.
- **`crates/pet-wayland` / `pet-macos` / `pet-windows`** — the OS-specific
  overlay/desktop layers that implement the core's traits.
- **`crates/bichinho`** — the daemon and the hook binary.

So: a new animation or reaction is a change in `pet-core` with a fake-clock test.
A new platform is a new crate implementing the traits.

## The golden rules

These are non-negotiable — they're what make Zeca safe to run:

- **Privacy.** Only metadata ever leaves the hook or the daemon: event names,
  ids, tool names, counts, a hash of an edited file's path, the project folder
  name. **Prompts, responses, code, error text, and window titles never leave
  the host, never go to a log (not even in debug), and are never written to
  disk.** The daemon binds `127.0.0.1` only and leaves no core dump.
- **No third-party characters.** Zeca is an original pixel-art parrot. Never name,
  describe, or draw him as a character from a studio or franchise. `bin/pet
  verificar` fails if such a name appears in the files or commit messages.
- **`unsafe`** is forbidden in `pet-core` and in the Linux daemon. It's allowed
  only in the platform crates, and every `unsafe` block must carry a `// SAFETY:`
  comment that actually matches the code.
- **Cost budget.** An idle, awake pet averages ≤ 2 screen commits per second,
  and 0 while asleep; bursts stay ≤ 30 fps.
- **Art.** Imported sprite packs and anything derived from them stay out of git
  (they live under `skins-locais/` or `tmp/`). Zeca's own CC0 art lives in
  `arte/zeca-livre/` and is generated by `arte/zeca-livre/zeca.py` — change the
  generator, never the PNGs by hand.

## Bringing a sprite

Zeca is just the default. A skin is a sprite sheet plus a small `skin.json` that
maps animations to states. The format (and how the default is generated) is in
[docs/SKINS.md](docs/SKINS.md). Custom-sprite tooling and a community gallery are
on the roadmap — if that excites you, it's a great place to jump in.

## Submitting a change

- Keep PRs focused. Each task gets a line in `PROGRESS.md`; a new decision or a
  change of direction gets an entry appended to `DECISIONS.md` (append only).
- Make sure `bin/pet verificar` is green.
- Commit messages: a sentence in Portuguese, citing the task or decision when it
  helps.

Happy hacking — and send a screenshot of your pet. 🦜
